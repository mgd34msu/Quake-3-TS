# Port architecture

## Usage

The game entry points are:

```sh
bun run src/main.ts client --data /path/to/Quake3 --home /path/to/user-config --product baseq3 --renderer cpu -- +map q3dm1
bun run src/main.ts client --data /path/to/Quake3 --home /path/to/user-config --product missionpack --renderer gl -- +map mpteam1
bun run tools/build.ts
./dist/quake3-ts server --data /path/to/Quake3 --home /path/to/server-config -- +map q3dm1
```

The `client` and `server` subcommands require a writable home separate from the retail data. Arguments after `--` use the original startup-command parser. [Run instructions](../README.md#run) describe menu startup and renderer selection.

The engine composes owned instances. Filesystem reads return validated assets. Shared movement consumes explicit player state, commands, and collision queries. Cgame publishes scenes; rendering and audio consume them. Dedicated composition never initializes video.

`CommonFrameDriver` owns common initialization, frame scheduling and source error dispatch. `CommonConsole` publishes its inert core to that owner before startup callbacks, and later input shares the same lazily sampled system clock. Source shutdown and final resource disposal are distinct: a recoverable source abort preserves its partial lifetime; explicit `close` consumes the remaining resources finitely without replaying abandoned source callbacks. Available bot resources belong to the server across map replacement, not to an individual game world. The driver contract alone does not supply a graphical client or listen-server application.

`UnixSystemClock` samples the wall clock once for `realTime`. A null destination skips calendar work; failed host conversion preserves the destination. `localTime` hides the Linux x64 glibc ABI behind an owned calendar record or null, using only `tzset` and `localtime_r`. This replaced the partial timezone interpreter after comparing a complete TypeScript implementation with the existing host service. The host service shares actual libc timezone state and avoids maintaining a second timezone runtime. The UI-only `localCalendar` convenience rejects a failed conversion rather than inventing fields for the source's uninitialized-stack case.

`UnixIo` owns the 256-entry system queue and Unix console, network, signal and readiness resources. `DedicatedEventSource` borrows that owner and supplies only the dedicated source polling order. The server's network services borrow the same instance. `CommonEvents` retains its separate 1,024-entry pushed-event ring. `SourceInputState` starts at Sys_Init before Netchan_Init, owns joystick state and survives window replacement. `in_restart` reapplies source input initialization without replacing the renderer or connection. `GraphicalEventSource` borrows the same `UnixIo`, shared input and optional window adapter, preserving queued events -> SDL keys -> console -> input frame -> packet polling, including joystick polling before a window exists. `SdlGameInput` owns the process-global SDL text/relative-mouse lease and borrows the window, keys, input state and clock. Focus loss releases shared joystick and window-local keys without duplicate releases. The graphical `EngineClient.keyEvent` adapter converts signed system time with `time >>> 0` for `ClientKeys`. Physical joystick acceptance remains open.

`ServerBrowser` borrows that same Unix I/O owner and the client-static clock. It retains browser lists and ping slots across individual connections. The graphical client routes admission's unhandled connectionless packets, including their original bytes, to this owner; menus do not poll sockets. Outgoing session packets use actual channel delivery, and packet-rate gating uses the admitted channel address rather than the earlier challenge address. Cache persistence uses actual common server-relative handles for home-root `servercache.dat`, retaining the source 152-byte records and partial-read mutations. Loading bytes does not eagerly interpret inactive addresses or string tails.

`RendererConfiguration` borrows an actual CPU/GL backend, its SDL window and initialized renderer settings. Base UI initialization retains its detached configuration copy at the source position. Graphics/Display menus use that copy rather than re-reading the renderer during menu initialization. Its process-wide exclusive gamma lease is single-display and focus-qualified; API acceptance is not physical readback. Current SDL refuses gamma setting.

`EngineSound` performs source sound initialization and command registration over common-owned `SoundOutput`, the real bank, music and scheduler. `SoundFrame` borrows that started output and its matching music, common events and cvars. Output retains pending PCM so it can replace future samples after excluding SDL-delivered frames. Nonempty queues advance only by actual dequeued samples; empty queues advance through elapsed logical silence. Pausing freezes that clock. Mixer sound time follows the resulting delivery cursor, while paint time may move over retained ranges. Physical hardware buffering and native DMA-wrap behavior remain qualified.

`CommonConsole` owns `CommonCdKeyState`. Filesystem startup reads the base key, then appends the selected mod key, after mount publication and before pure reordering. Client archive saves write configuration before awaiting the actual UI's `usesUniqueKey` entrypoint and reading live `fs_game`. Only callback result 1 selects a nonempty mod's unique key. Dedicated startup uses the source null-client validator and never saves keys. Typed and bytecode menus share the same fixed-width bytes. Initialized ordinary file reads apply the original key-file restriction; common key loading uses server-relative handles. Verification uses synthetic credentials and private data roots, never installed keys.

`CommonConsole` owns an inert `SoundOutput` before filesystem startup. `CommonFileState` borrows it and the real `CvarRegistry`; server-relative reads clear that actual output through the common handle table. Dedicated startup never opens an audio device. `SoundOutput` owns its SDL device and mixer when started; `EngineSound` and `SoundFrame` perform graphical initialization and scheduling. Cgame borrows `EngineSound` rather than requiring a device-backed mixer, so disabled or unavailable output does not prevent level initialization.

`AudioMixer` borrows the actual allocation clock. Pending channels start when a selected paint range is scanned, rather than when their sound is allocated. Explicit ranges allow future PCM to be repainted; channel retirement occurs on the next source scan. `SoundOutput.start` requires the same clock. This timeline supplies the prerequisite for device-queue scheduling, not the scheduler itself.

## Ownership and interfaces

`ServerWorld` receives the actual synchronous server print owner. A capped area query emits MAXCOUNT only after resolving an intersecting overflow candidate, then stops only the current recursive sector. Sound registration receives separate ordinary and developer diagnostics; EngineSound applies the live common developer integer gate. Decoded WAV source width belongs to the format result, while generic PCM consumers keep their existing representation.

`ServerEngine` owns `ServerWorldSectors`, containing only 64 stable sector cells and 1,024 numbered membership cells. Map-local `ServerWorld` borrows it while retaining collision, entity metadata and its game resolver. Full source server clear zeros membership next/sector pointers but preserves global sector heads. World clear resets the same sector cells. Fast restart does neither. Scoped area traversal stops only its current recursive sector at capacity and can continue through its parent's sibling.

`CommonConsole` owns `CommonJournal`. Initialization follows the initial default.cfg length probe and precedes startup config execution. `CommonFrameDriver` wraps actual platform event acquisition, leaving pushed-event ownership unchanged. Mounted VFS instances borrow the config journal through `CommonFileState`; only explicit FS_ReadFile operations participate. Common owns the descriptors and preserves their source shutdown order. Generic asset reads and source FOpenFile callers do not implicitly become journaled reads.

`SourceFileReader` exposes required length, asynchronous optional-content and synchronous optional-content reads. The actual server map, demo numbering, renderer assets/fonts/models/skins, retail module selection and sound bank use these source operations. Client forwards select the current mount and check the current operation before and after reads; the sound bank rejects publication after its registration lifetime ends. Model LOD reads preserve source spelling separately from existing normalized published identities. Cgame animation.cfg remains on its source FOpenFile path.

Keep original subsystem responsibilities so translated behavior remains traceable. Replace global state and VM trap numbers with typed instance methods. Preserve server-static, server-world, client-static, client-connection, and client-active lifetimes separately. Server and prediction use independent movement scratch state and explicit clocks/random generators.

Game owns authoritative entities. Server consumes published state and owns world links, connections, configstrings, and snapshot histories. Local clients still communicate over loopback protocol. Published snapshots must not alias mutable future simulation state. Choose ordinary typed records for entity/game logic first; pack measured hot paths and fixed wire storage where it helps without changing algorithms.

Small vectors use named `x`, `y`, `z` fields; geometry uses packed typed arrays behind checked boundaries. `Vec2`, `Vec3`, `Vec4`, bounds, planes and matrices live in core math. Wire representations stay in protocol. Semantic product stats have explicit baseq3 and missionpack index mappings. Never merge variant enums by appending the Team Arena-only slot.

Binary readers use bounds-checked DataView operations and throw structured parse errors containing source and offset. A format parser catches errors at its external boundary when needed. Do not return a result wrapper around every scalar read. Check integer ranges, nested offsets, stride divisibility, finite fields and cross references before exposing a parsed asset.

Trace results distinguish clear, impact, start-solid exit and all-solid outcomes. An all-solid result cannot carry an invented impact plane. BSP collision uses source `cm_*` brush/capsule and independent patch-facet algorithms. Visual tessellation never supplies collision.

## Client composition contracts

`ClientHost` composes `CommonFrameDriver`, actual Unix/SDL events, `EngineClient` and the listen server. Client static, connection and level lifetimes remain separate. `ClientAdmission` borrows client records, cvars and actual transports; its admitted result supplies the channel and responder address to `EngineClientSession`, which borrows the same reliable ring. `EngineClient` owns connect/disconnect, loading, frame execution and source shutdown separately from final disposal. One authorization owner retains DNS state across connection resets and reads only common-lived key bytes; no credential file is imported. Connection-owned downloads consume typed blocks, write contained temporary files and complete the real filesystem restart/reliable-command sequence. Retained demo playback borrows the same common file table. The session retains configstring presence separately from text: `getConfigString` distinguishes an allocated empty entry from a missing entry, while `getGameState` is a value-only copy. UI reads these actual records rather than maintaining another connection state.

Demo readers synchronously publish each complete signed sequence word to the actual session before reading length or reporting EOF/error. The required callback returns `undefined`, excluding asynchronous callbacks. `SnapshotHistory` retains current player state independently of its masked snapshot/entity lookup window; engine input and console borrow that retained state even at sequence zero or after entity history expires. Cgame's guarded snapshot reads and regression checks remain separate.

Renderer startup registers source video cvars before opening SDL. Existing custom inputs win individually over initial host dimensions. The actual window retains its dimensions, source aspect and stencil precision across map flushes; `vid_restart` replaces that owner and republishes actual backend/UI dimensions. Console mode changes and SDL Alt-Enter use that same path. Pixel and texture settings remain guarded until their real implementations are available.

The playable cinematic owner borrows the concrete `EngineSound`. Audible stereo before the first RoQ INFO chunk calls its update, checks cinematic lifetime, rereads the current mixer and resets the raw cursor before validating/decoding stereo. Pure decoder/playback hooks expose that exact boundary. Mixer-only diagnostic compositions are explicitly tagged and reject the reached sound-update requirement; they do not supply fake frame updates.

At module creation, `acquireClientModule` and `acquireGameModule` borrow the common-owned three-slot `VmRegistry`. They sample hunk availability before reservation/reuse and print loading diagnostics before reading the actual pure-filtered artifact. Recognized retail identities select TypeScript by product and role; other valid artifacts return a parsed bytecode image. Bytecode owners construct the interpreter, release the retained file image, load developer symbols and publish final loading diagnostics in that order. Missing files return null after source diagnostics and slot release. Rejected reads retain source package-reference effects. External UI/cgame use `QvmUi`/`QvmCgame` with scoped recursive calls. Renderer configuration survives renderer closure; `ClientActiveState` is engine-owned and remains available after connection clears. The supported Team Arena 2000 artifact identities do not establish equivalence to the 1.32b source baseline.

`ClientMotd` borrows the actual client-static records, common clock/random and Unix I/O. Its request runs at source connect ordering, resolves the update address afresh and sends actual renderer/version fields. Replies require the retained address and challenge. This lifetime survives connection resets and clears only at client shutdown; acceptance does not require a currently connected game session.

An owned loading callback can explicitly report that its connection retired after checking common execution authority. That result cancels the old packet, preserves the source pause reset and leaves stale-operation rejection intact. Discarding remaining operations of that retired packet is a managed-lifetime qualification, not exact reuse of C globals. Normal nested messages on the same connection still continue against live state. Common source shutdown closes its log and then, on normal quit, the filesystem; final disposal happens after Unix's second client shutdown attempt.

`BaseUi` owns the actual base menu graph and source UI entry points. Engine-lived `EngineScreen` initializes before renderer registration and borrows the current presentation resources. `ClientLevel.drawActiveFrame` queues cgame drawing; source loading callbacks provide their actual partial draw operation to the screen. The screen then draws UI and console before one command submission and SDL presentation. Renderer replacement does not reset screen initialization or graph samples. `ClientDemoRecording` writes through common binary handles and is reached after parsed network messages; its screen indicator reads that same recording owner.

`EngineCinematics` delivers each audio chunk immediately to the current mixer's fixed raw ring, allowing construction before sound startup and continued video with disabled output. It has no pending PCM queue or decoder backpressure. INFO dimensions and frame pointers publish before later audio callbacks. Cinematic raw resets use sound time, not the paint-ahead clock. Production movie playback owns unique common handles through a current-filesystem getter and bounded RoQ chunks. Filename formatting uses the Linux 4,096-byte buffer and ordinary common diagnostics before reuse or opening. Source developer messages use a separate required callback, with live developer gating at EngineClient. Diagnostic byte readers have an explicit separate prefetch profile. System playback awaits actual menu closure at the source position before decoder initialization; non-system playback remains synchronous. Final disposal retires movie and music borrows without callbacks into a closed host; common still owns actual handle cleanup.

`ClientGameState` and `ClientGameStaticState` are sibling objects. Static state owns the 64 stable client-info cells; active state owns snapshots, predicted state, transient presentation and the current `Refdef`. Client-info loading prepares detached records and publishes into the stable cells only if both request and lifecycle generations still match. Snapshot history and rendered scene publication copy data that must outlive its producer's mutation.

Snapshot processing awaits reliable server commands at the original transition point. Commands may register media or load client information; they must finish before transition events and prediction observe that state. Voice events propagate their awaited work through player-state transitions, snapshots and prediction. Head-model voice mappings use synchronous first-use reads with source cache and retry behavior, not prefetch. Synchronous event callbacks must not hide an unawaited Promise behind a void-only signature.

Rendering media is registered before synchronous player, weapon and effect presentation. The local-entity and particle pools retain the source's allocation and traversal behavior, including effects that allocate more effects during traversal. They consume the shared cgame random stream where the source does; separately seeded source generators stay separate. The frame composer must supply actual prediction collision, marks, sound and registered media services, not empty callbacks.

`ClientLevel` composes cgame initialization and drawing for the graphical application. Both products join their actual UI and cgame owners and enter maps on CPU and GL. STATUS.md records the accepted gameplay gates; COMPATIBILITY.md records the remaining comparison qualifications.

Team Arena metadata, catalogs, model lists, mod/movie/demo lists and saved scores borrow the actual common file owner. Selection writes active flags on the original metadata rows. The player list reads snapshot client identity and actual session configstrings. `TeamArenaUiResources` shares renderer, engine sound, cinematic and font owners, publishing asset fields at the reached parser calls rather than after an entire file succeeds. Font registration returns a nullable no-write outcome: callers retain their prior font while later source parser side effects continue. `RendererResources.fonts` owns the six shared registration slots for UI and cgame. Registrations run in source call order and check capacity before cache hits. UI recreation and world loading retain that owner; renderer replacement, including retained-window map flush, replaces it. Parser and render-thread barrier qualifications remain separate.

The retained Team Arena menu loader publishes into the same UiRuntime/string pool. Browser display indexes refer to actual engine records; status/search borrows the engine's sixteen request slots and retains source text/pointer cells. UI movie handles are actual persistent engine cinematic slots, including negative owner-draw close routing. Shared feeder selection/painting and owner-key entrypoints await downstream resource/status work before continuing; cgame's no-menu score selection remains synchronous. The product feeders consume those actual owners, including map score/movie selection and status requests. Visibility consumes actual player/score state and settings preserve source cvar write order.

Team Arena player previews have their own source model/head/team-skin and animation state, sharing only source-identical interpolation with the base UI. The refresh owner advances the UI clock and FPS history before cvar updates, menu painting, browser/status work and cursor drawing. Console commands update that same display time before scripts, and call actual reload, postgame, shader remapping and menu-cache owners. `TeamArenaUi` now composes these owners with drawing, key dispatch and scripts. EngineClient publishes the owner before menu loading, initializes the actual source asset/metadata/menu sequence, and saves the server cache at Team Arena UI shutdown. Callback-free retirement invalidates the UI lifetime without inventing global music or movie stops. Shared `playLooped` stops the actual engine music stream at its source call site. The mission-pack cgame HUD keeps its own runtime and audible cinematic profile.

## External-mod bytecode

`CommonConsole` initializes its `VmRegistry` before the server. Actual UI, cgame and GAME entrypoints mark their registered owner; internal helpers do not impersonate VM calls. Source shutdown and callback-free retirement remain separate. Fast GAME restart retains registration identity while recreating direct TypeScript game state, or reloads bytecode data while retaining its interpreter and symbols. Retired direct owners cannot free their successor's registration. Developer symbol loading supports source map relocation and diagnostics; the selected non-DEBUG_VM build does not collect instruction profile counters. TypeScript execution does not claim native DLL or JIT behavior.

`parseQvm` owns image validation and decoding. `QvmInterpreter` owns copied data, source prepared-code slots and per-invocation operands. `invoke` accepts ten source argument words and returns a promise; the syscall callback receives live little-endian words, shared memory and a scoped recursive `invoke`. Numeric callbacks remain synchronous inside the loop. Recursive children run sequentially below the published stack pointer; unrelated entry rejects, and parent completion waits for descendants. `restart` reloads data without replacing code. Pure arithmetic lives in `vm/operations.ts`.

This is external-mod support, not a replacement for retail TypeScript modules. VM traps borrow actual common, filesystem, renderer, sound, client, collision and bot owners. Command tokenization retains the last command, including recursive calls; cvar records use the same registry indices as typed modules. There are no VM-owned handle pools. Picture commands reserve queue position before shader lookup can print; font registration synchronizes the render target before cache, capacity or read operations. Source-profile qualifications remain in COMPATIBILITY.md.

`GameRuntime` and `QvmGame` implement `ServerGame` directly. `ServerGameData` supplies shared entities and player-state reads; `QvmGameData` borrows the interpreter allocation and retains entity views across table relocation. The pinned shared-entity prefix is 516 bytes, including the unused embedded entity state. Link flags, counts and absolute bounds live in those actual records; server metadata stays in `ServerWorld`. Clients retain entity pointers rather than a binding boolean.

Server call bodies use `CallSteps`: ordinary TypeScript imports finish synchronously, while packet/frame/command owners await reached VM calls. No replay or deferred callback queue is involved. Nested disconnects and bot commands finish before their source tails resume. `QvmGame` is published before INIT, reloads data in place on fast restart, and separates source shutdown from callback-free retirement. Root integration checks remain separate from these implemented contracts.

The user-command, entity-state and player-state codecs read/write the source 24-, 208- and 468-byte layouts from already-resolved views. Integer angle vectors retain all 32 bits; float vectors store binary32. Decoded records own their vectors/slots, short writes reject before mutation, and unknown typed enum extensions reject explicitly. Scalar math dispatch preserves the different game versus client/UI trap numbers.

## Rendering and SDL2

One scene/material frontend owns world visibility, patch LOD, MD3 animation/tags, shader stages, deformations, fog, lights and ordered views. The backend contract contains indexed geometry, transforms, texture sources, viewport/scissor, and explicit depth/alpha/blend/cull behavior. It can contain several views and 2D operations in a frame.

The CPU renderer performs clipping, perspective-correct interpolation, sampling, depth, alpha tests, and blending in TypeScript. SDL2 only presents the framebuffer. The GL renderer submits geometry and equivalent stages to OpenGL through an SDL2-created context. Use the fixed-function API to preserve the source renderer's behavior without introducing GLSL project source.

EngineClient owns one lazy CPU triangle executor across map, video and product restarts, and closes it during final resource disposal. The rasterizer captures bounded ordered setup lists only after source binding/cinematic callbacks. Workers render disjoint private row bands; successful completion publishes all bands. Failure discards private output and replays the owned pixel kernels serially, preserving the first actual error and retained attribute checkpoint. Source callbacks and command producers are never replayed. Small draws and unsupported shared-storage profiles retain serial execution. This does not implement the original threaded `r_smp` frontend/backend mode.

The CPU triangle profile defaults to eight fractional window-coordinate bits, nearest-even rounding and lower-left shared-edge ownership. Coverage and interpolation use the snapped coordinates. Comparisons can pass the driver's reported subpixel precision, but equal precision does not prove identical rounding or edge rules on every driver. The [OpenGL 2.1 specification](https://registry.khronos.org/OpenGL/specs/gl/glspec21.pdf), section 3.5.1 and table 6.33, leaves implementation-dependent precision while requiring consistent shared-edge coverage. Analytic and native probes identify the measured profile; line rasterization remains separately tested.

`RendererResources` owns model, skin, shader and texture registration before a world is loaded. It borrows the engine's immutable image catalog, built-in images and real shader cinematic registry. One `EngineCinematics` owner serves shader movies, UI, cgame and the system cinematic controller. `loadWorld` uses those resources; UI picture registration uses the same cache instead of decoding a second copy. Canonical `RefEntity` variants distinguish models, sprites, beams, portals, lightning and rails. Backend batches distinguish triangles from lines. Unsupported material or entity semantics must be reported, never converted silently into a different primitive.

The canonical `Refdef` carries the exact view basis, viewport, horizontal and vertical field of view, flags, area mask and render strings. Client view calculation publishes that type and `WorldFrame` consumes it directly. Scene capture returns a producer for ordered `RenderView` records with viewport, clear behavior and draw/volume/finish operations. An optional `beforeView` sequence contains only surfaces that must execute under retained backend state before the new view clears. One engine-lived `RenderCommandBuffer` consumes those producers through a fixed `RenderTarget`, preparing work once and applying it to both real backends. `Draw2D` instances are coordinate profiles over that same queue, not independent command owners. Submission returns counts, not replayable commands. There is no Euler-camera or legacy draw/finish adapter.

The resource owner binds the ordinary surface evaluator to its actual `SourceTessState`, sharing world, picture, sky, fog and dynamic-light execution. Internal stencil markers branch before ordinary deformation/stages and retain source tess counts. Physical cull and depth state remain distinct from cached cull identity. Portal probes and child frontend preparation execute before scene completion, using the actually retained backend state. Immediate beam/axis and overflow effects use the target's checked execution session without draining pending views. Retained probe geometry flushes at the next actual source boundary; child views inherit their parent's probe. `beginFrame` resets source finish bookkeeping, ordinary `submit` remains a mid-frame drain, and `submitFrame` performs the source tail flush and conditional finish before presentation. Actual SDL/backend stencil precision governs volume execution; a retained window keeps its precision until `vid_restart` replaces it.

Production view and surface evaluators yield operations one at a time. The consumer completes each operation before advancing the producer, so later preparation failures preserve earlier draws and retained state. Source operations borrow their data until the next advance; diagnostic array views retain owned snapshots. Physical cull, depth-range, sky-box state and polygon-offset operations can execute without geometry. `source-stage` records run material bindings, cinematic uploads and cleanup even at zero indices, while ordinary empty draws remain suppressed. Backend preparation captures geometry but leaves texture selection and paired texture environment reads at their reached source phases. Singles apply state after binding; pairs apply it before binding. Cinematic completion precedes the next texture phase. Zero-length arrays do not cross pointer FFI. Normal source tails restore depth/offset without exception-finally restoration.

Signed `Refdef.time` supplies shader time. The engine cinematic owner samples its live cinematic clock at the original execution sites, not during scene capture; `WorldFrame` has no captured cinematic scalar. Ordinary 2D entry samples its renderer clock only on the source projection transition. Raw cinematic drawing drains older commands, performs the source finish barrier, captures live pixel bytes, uploads through the actual selected texture object and enters 2D unconditionally. Immutable image creation and current-object border operations form the static journal. Dynamic uploads are one-shot execution work and are not replayed into a new backend.

Material registration identity includes the finished lighting mode and the owning BSP lightmap. Remapping changes the material used by existing registrations while retaining source frontend sorting and cache behavior. Failed public shader registrations use the source zero handle, represented by `null`; the renderer's real default shader and its cached named failures are distinct internal records. Projected model shadows consume actual entity lighting and retained orientation. Stencil volumes and the darkening finish execute on both CPU and GL through ordered operations. Full stitched patch grids remain world-owned for marks/allocation; execution selects view-distance geometry using the live LOD cvar and transformed inline-model centers. The undefined reverse-edge source error lookup uses its matched midpoint only when the original index lies outside the allocation. World portal/mirror views preserve source selection, reflected basis, remote PVS origin and child-before-parent execution. CPU and GL consume the same owned homogeneous clip plane and reset it for parent, 2D and raw drawing. Sky preserves its original vertices with far depth range. Projected dynamic lights share source BSP/inline masks and transformed-light cells across child/parent views; their depth-equal passes execute after material stages and before fog. Text deformations read the actual retained four tessellation cells and bounded refdef rows; each deformation publishes its writes before the next. World view entry installs text after prior geometry flushes, and later 2D drawing retains that text. Portal-sorted entity/MD3 prepasses consume retained backend entity pose and issue beam, axis and depth-range operations in source order. Reached flare submissions retain sorted state but emit no geometry, matching the selected empty source handler and inactive dynamic-light producer. Image preparation owns source resampling, mip chains, formats and color mappings; CPU and GL consume that same catalog. Cvars register before SDL selection, then actual capabilities initialize renderer settings. Recorded retained-attribute gaps remain explicit.

Only platform modules import `bun:ffi`. Bun 1.3.14's installed `dlopen` and `linkSymbols` declarations map descriptor tuples to exact argument/return types, including `Pointer | null`. Validate native results before wrapping handles; do not fabricate pointer brands. Keep backing buffers alive for each foreign call and queued data until ownership transfers. Use SDL queued audio to avoid callbacks on foreign threads. Decode SDL event union buffers with explicit ABI layouts and test real pushed events. Context initialization precedes GL procedure lookup. Cleanup is idempotent and handles partial startup.

## Synthesis

MD4 registration dispatches by the loaded identifier and preserves independent MD3 LOD slots and the source MD4 allocation pointer. The skeletal resource owns the copied allocation and animation arithmetic; `SourceTessState` owns source index/count ordering and partial vertex writes. `SourceSceneSubmission` borrows `RendererResources.sceneEntities` and owns the matching frame-wide polygon/light allocation. Actual UI/cgame clear/add/render calls share it. Clear and successful scene completion advance membership without reclaiming frame capacity; frame rollover follows backend consumption. Backend selection retains entity cell identity and its prior lighting. CPU/GL publication selects only referenced allocation cells in original slot order without rewriting source tess indices. Retained stencil adjacency belongs to the same tess owner. Unsupported allocation and retained-pose profiles remain explicit gaps.

The source-aligned candidate is the preferred base because its instance boundaries preserve original responsibility without requiring a whole-game data-layout rewrite. From the data-oriented candidate, adopt explicit snapshot publication, no mutable arrays shared between simulation/prediction/rendering, packed renderer batches, and protocol loopback for local play.

Reject mandatory structure-of-arrays storage for all gameplay until profiling establishes a need. Reject result wrappers for every scalar binary operation and optional-plane trace bags. Reject universal ECS conversion, a generic syscall bus, and original QVM execution as the shipped game implementation. These choices add translation work or weaken the requested typed boundaries.

Independent scoring and any resulting corrections are recorded in the decision log. Candidate artifacts are local planning evidence under `/tmp/quake3-design-iS7hL6/`.

## First contracts to implement

```ts
interface Vec3 { readonly x: number; readonly y: number; readonly z: number }
interface Plane { readonly normal: Vec3; readonly distance: number }
type Product = "baseq3" | "missionpack";

interface AssetReader {
  read(path: string): Promise<Uint8Array>;
  has(path: string): boolean;
  list(prefix?: string): readonly string[];
}

interface CpuPresentation {
  present(rgba: Uint8Array): void;
  close(): void;
}
```

The lead freezes concrete signatures with each worker before dependent implementation. No unimplemented runtime stubs are needed to express planned later phases. Type errors that repeatedly require workarounds trigger redesign of the boundary.
