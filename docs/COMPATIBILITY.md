# Defined compatibility corrections

This reference records deliberate differences from undefined or unsafe behavior in the pinned C source. These are not claims that the surrounding subsystems are complete.

Source shader tcMod lines use the original 1024-byte copy buffer limit; a reached overflow rejects instead of writing outside it. Raw SkipRestOfLine advances through LF without parsing quotes or comments. At NUL it uses the parser's existing managed exhaustion state instead of exposing the original pointer past the terminator. GL strip emission closes an active primitive on a managed rejection, preserving the error and prior attribute writes so subsequent rendering can recover.

Calendar traps use the Linux x64 glibc host service through typed `localtime_r` and `tzset` calls. Leap seconds, implicit DST rules, invalid-zone fallback and dates beyond JavaScript's range follow the native service. A failed conversion leaves the `Com_RealTime` destination untouched; null destinations skip calendar binding and conversion. Current Bun assignments to `process.env.TZ` after startup do not change libc's separate environment; timezone fixtures therefore set the child environment at launch. Other native ABIs are not claimed.

Retail self-stitching can replace a patch while the original `R_TryStitchingPatch` still retains its old pointer. `Z_Free` poisons that payload and later allocations can reuse it. The port snapshots the selected numeric LOD origin/radius before stitching and continues reading source/target meshes from their live slots. This restores affected retail maps without claiming parity with poisoned or reused native addresses.

Retail q3tourney4 contains visible leaves with area -1. The selected little-endian renderer profile places `rdflags` immediately before the 32-byte area mask, so that reached source subarray overread tests bit 31 of the actual flags. The port retains those predecessor bytes explicitly. Other unsupported area addresses still reject after source PVS checks; this is not a claim of defined portable C indexing.

`R_LoadLightmaps` invents a second image for a one-lightmap BSP without adding file storage. For that generated companion alone, the port preserves bytes still inside the retained file allocation and zero-fills the unavailable tail. It reports that correction when reached. Ordinary lightmap reads stay strict. Both retail `test_bigbox` variants use only image 0, but retain the published companion image 1. This does not reproduce native bytes outside the allocation.

Shared GAME entity views borrow the pinned 516-byte prefix; table relocation does not change existing pointers. Full-record borrowing preflights the prefix, while indexed ping writes touch only the ping field. Numeric enum values now remain raw through engine/QVM transport, with retail-state checks at the TypeScript cgame consumer. Arbitrary NaN payload preservation remains qualified. External GAME fast restart retains interpreter code and allocation; active restart and allocation growth reject explicitly. Synchronous call owners reject a reached asynchronous wait before launching it, preserving any already-reached synchronous prefix.

Bot VM adapters retain source lazy reads and callback ordering. Raw presence integers survive initialization and area-mask queries; a reached unknown-presence bounds query prints the source fatal diagnostic and selects crouch bounds. Null-origin routing repair, uninitialized route/movement data, finite geometry and the documented portal-index repair remain qualified. Mark fragments retain the bounded finite-projection profile and explicitly reject a missing world.

QVM cinematic calls share the actual engine slots. Retained reset now closes/reopens the selected file and performs the source unchecked 16-byte read into retained header storage, including reset during menu closure and after rejected initial headers. Empty-filename reset still rejects the source's undefined filename-underflow path. It does not fabricate Idle success or reopen a different movie. Sound playback runs lazy loading for nonresident rows through the actual bank. Resident nonzero rows without PCM still reject explicitly; native page eviction, overlapping async loads and retired-lifetime reuse remain qualified. Invalid handles preserve original print/return behavior.

QVM filesystem traps retain the contained-path/Linux cursor profile. Packed reads use TypeScript DEFLATE, a 64 KiB compressed-input buffer and 32 KiB history without whole-entry decoded storage. Packed rewinds reuse the captured descriptor and reread saved central-directory metadata before validating the local header. Retained reads stop at the declared output size without a terminal probe and omit payload CRC accumulation/checking, matching the source. Diagnostic archive readers retain stricter size/end/CRC checks. Canonical Huffman tables, managed decoder allocations, precise symbol consumption and rejection of uninitialized-history references differ from bundled zlib allocation/lookahead/failure timing. Partial close does not drain; exceptions still close independent descriptors. Source `fs_copyfiles` copies selected CD loose files through an independent read and contained base-directory write. PK3 entries are not copied.

CommonHunk owns the actual port arena. Retained FS buffers, renderer uploads, shader data, VM allocations and sound/screenshot temporary buffers use it. Collision and renderer BSP loaders allocate and consume their own source-ordered records; eager full-format parsing remains diagnostic only. Renderer temporary patches use source zone storage. Some managed records remain outside the arena, and direct TypeScript modules do not allocate QVM code/data. These remain native allocation-pressure qualifications. Source font DAT and rejected PCX read-buffer leaks are retained. A matching client collision load borrows the actual common-owned server world.

Renderer backend allocation now supplies actual entity, polygon, light, command and draw-sort bytes. Commands use the 256 KiB source budget and fixed release32 sizes; draw surfaces use the 65,536-slot array and source quicksort. Shader insertion repairs queued sort words, including the source's unshifted entity-bit quirk. Typed bindings represent surface/shader pointers and owned refdef/view snapshots; their reserved ABI bytes do not claim populated native structures or native addresses. Manually queued diagnostic prepareFrame callbacks without a draw range cannot participate in shader fixups. Non-threaded SMP fallback retains requested double-buffer allocation and source selection, but does not claim a threaded renderer. Screenshot commands consume their numeric rectangle and format; out-of-framebuffer rectangles and unsafe source RGB row packing reject explicitly.

The common main zone and 512 KiB small zone have actual Release32 block headers, free-list allocation, coalescing and free-byte queries. Bot heap records use the main zone; cvar strings and command records/names use the small zone. Empty and single-digit CopyString values are static and incur no heap allocation. Bot/AAS scalar, vector, text and array consumers read allocated bytes, but typed pointer identities and some remaining tables are qualified. Freed allocation handles reject access; already borrowed byte views cannot be revoked. Defined source partial-allocation residue and selected leaks are retained rather than hidden by automatic cleanup. Incomplete unlinked Cvar_Get slots retain consumed indexes/allocations but are not exposed as partially initialized VM rows.

Console and packet events use shared main-zone payload allocations through Unix queues, common queues, journal recording/replay and dispatch. Normal dispatch and dropsim free them; source error and oversized-packet continuation paths retain them. Awaited handlers receive the actual event-loop scratch copy. Lexer storage uses the Linux i386 2148-byte script record, original-length text buffer, 1024-byte punctuation table and embedded1068-byte token. Preprocessor source/hash/conditional records and shared incremental menu handles now consume their allocated bytes. Includes and root readers release them at reached source boundaries. The wider integer, escaped-NUL and extended-float qualifications below remain.

QVM renderer records retain signed numeric handles and complete source entity fields. Lookup occurs at the reached renderer branch or MD3 surface. RT_POLY is admitted, then raises the source drop if entity rendering reaches it. Unused signed RF and RDF bits are ignored. Unterminated refdef text rows and consumed nonfinite geometry remain explicit managed rejections. Successful tag interpolation retains the existing finite-fraction profile; missing tags return before inspecting the fraction. A picture executed reentrantly before shader lookup finishes rejects instead of consuming an uninitialized command.

World entity tokens use the actual renderer cursor. World loading sets its duplicate-load guard before reading, retains reached allocations on failure and publishes the completed world before releasing its file. Collision visibility includes its eight allocated zero tail bytes. Renderer visibility allocates separately unless setWorldVisData explicitly supplies a buffer; the pinned source has no caller for that setter. Cross-row reads inside the respective owned allocation are supported; hunk alignment bytes beyond it are not represented.

PC handles share the actual bot library's source table, base folder and allocated global definitions. File sources use COM_Compress; memory definitions do not. Retained 1068-byte token records preserve partial writes, unused tails and copied source tokens through all three VM roles. Invalid handles leave output untouched. Uninitialized synthesized fields still reject on consumption; wider integer and escaped-NUL metadata and binary64-to-x87 encoding remain explicit numeric profiles. Bot script and AAS filenames preserve ordinary common Com_sprintf warning text, truncation and source call order. Route-cache writing counts records before the filename callback, then serializes live state. This filename evidence does not establish a project-wide formatting audit. The diagnostic eager parser drains the same incremental reader; production menus consume shared handles incrementally.

The CPU legacy `glconfig_t` compatibility record retains actual software renderer strings and capabilities, while encoding the ordinary driver branch as 0 and maximum texture dimension as the existing signed-int32 image ceiling. These fields do not claim a native GL driver or available allocation capacity. The actual TypeScript CPU configuration remains `driverType: "cpu"` with no GL texture-size limit.

The external-mod QVM reader/interpreter preserves the pinned release interpreter's prepared int slots, raw byte return PCs, initialized reserved operand cell and anomalous preceding-cell `OP_BCOM` write. Arithmetic uses the existing wrap32/binary32/CVFI profile; NaN payload identity is unspecified. Malformed image ranges, consumed uninitialized operands, out-of-allocation accesses, misaligned program stacks, undefined integer division/remainder and invalid shift counts reject. Restart rejects a larger replacement allocation rather than overwriting native memory. Host entry/result values must be signed words. Asynchronous syscall ownership rejects overlapping or expired recursive entry and drains descendants before cleanup. External UI, cgame and GAME adapters now dispatch through actual engine, renderer, server and bot owners. Native DLL/JIT execution modes are not the TypeScript implementation.

Common VM traps now borrow actual command/cvar owners. `strncpy` returns the original signed VM destination word, not the source's unavailable host-pointer address bits; overlapping copies and invalid required spans reject before mutation. `Q_strncpyz` retains byte-counting, truncation and NUL padding. Vector traps use the existing SSE binary32/no-FMA host profile with double M_PI, not x87 or universal libm parity; the degenerate perpendicular denominator rejects under the assertions-enabled profile. Nonfinite Cvar_SetValue input rejects. Cvar info strings use source bytes and ordinary-prepend versus big-append ordering. Source buffer overruns remain explicit managed rejections. No external-mod launch or retail-bytecode gameplay is implied.

QVM user-command/entity/player record codecs preserve the selected 32-bit little-endian layouts and all non-network fields. Movement, weapon, weapon-state and trajectory values retain their raw source integers through transport; user-command weapons retain their full byte. Retail consumers perform their own reached checks. Writes preflight the full extent; float fields do not promise arbitrary NaN payload-bit retention. The server-bot regression now checks that weapon 255 reaches the actual retained user command, while invalid pointers still reject before replacement. Root's current selection passes 12 cases and 77 assertions.

Splash falloff now rounds the subtraction before multiplying damage, matching the selected QVM DIVF4/SUBF4/MULF4 sequence. A grenade-profile distance of 69 with damage 100 and radius 150 produces 53 damage, not 54. This is selected-QVM behavior, not a claim about every native compiler's intermediate precision. MAXCOUNT output and developer error severity now reach actual common owners. Sound warnings preserve mono rejection, width-before-rate output and live developer gating. ADPCM and wavelet codecs are translated with caller-owned chunks; their registration/mixer branches remain dormant, matching the source's forced uncompressed registration. Undefined transform sizes, missing padding and out-of-range conversions reject explicitly.

Image-grid drawing now runs at frame end when selected and unconditionally at Unix renderer registration completion. It preserves requested upload dimensions, current texture unit, retained color and color-only clear behavior. CPU source-indeterminate retained attributes still reject explicitly. Existing common memory-touch, image frame-use accounting and eager frontend failure-publication qualifications remain separate.

Shared `Info_Print` retains source key padding, individual output calls and dangling-key diagnostics. Reached 512-byte key/value overflows reject, preserving output already produced. Server info uses the ordinary cvar-info limit, and dumpuser reads actual remote userinfo rather than local cvars or player configstrings. Dedicated say registration samples the source initialization-time cvar. Source Cmd_Args/text-buffer overflow rejects; the actual reliable-command owner retains its existing truncation behavior. These commands do not resolve existing byte-string and cvar-info qualifications or full server parity.

### Renderer comparison profiles

M9 accepts the selected fixed-function GL implementation, not exact agreement with every GPU or historical native compiler. Original 320×240 q3dm1 and mpteam1 world captures use recorded cameras, clocks, settings and Team Arena remaps. Against the original Mesa profile, the accepted ordinary GL rounding band is one RGB byte. q3dm1 has nine differing pixels, all within that band. mpteam1 has 85 within-band pixels and two separately explained exceptions: `(82,10)` differs by 10 because three original cgame shadow submissions change equal-key sort order; `(237,23)` differs by 6 under the recorded cinematic x87 byte-copy qualification. These named exceptions are not a general maximum-error allowance for other scenes.

Root independently reran original 1,104-input sorting through the production implementation with zero pointer-order differences. Removing only the three extra shadow submissions exactly reproduces standalone world ordering. Original floor geometry, both UV arrays, colors and 415,060 uploaded bytes also match; alternate nearest-mip choices reproduce the largest CPU residual. Evidence: `/tmp/quake3-residual-actual-vOO1a1/REPORT.md`, its `compare-sort.ts`, `compare-floor.ts`, `floor-analysis.ts`, and root captures in `/tmp/quake3-functional-join-qHlpx2/`.

CPU sampling retains analytic quotient derivatives and ideal-rho LOD. Driver approximations near nearest-mip thresholds can produce larger color changes: diagnosed world maxima are 40 on q3dm1 and 29 on mpteam1; head/cigar stages additionally amplify differences through additive blending. These are observed values, not universal tolerances or permission to ignore unexplained differences. ## Game and engine numeric profiles

JPEG decoding uses the pinned build's enabled floating-point AA&N IDCT, not integer IDCT. Quantizer multipliers use the source double expressions followed by binary32 storage; transform operations use binary32 without fused multiply-add. The verified native oracle uses LP64, where the source's `INT32` typedef is `long`. Accepted coefficient/quantizer bounds keep intermediate values below `2^39`, so truncation, descale and the low-ten-bit range mask are exact in TypeScript. An extreme 16-bit-quantizer input agrees with that defined LP64 result but exceeds signed 32-bit conversion range. This is not historical x87 or ILP32 extreme-input parity. Evidence: `tests/jpeg.test.ts`, `/tmp/quake3-jpeg-float-proof-DGfVpm/`, and `/tmp/quake3-jpeg-review-YLyCe1/`. Source now also implements progressive DC/AC first and refinement scans, EOB runs, restarts, quantizer retention and smoothing from the bundled IJG code. The pinned build disables those progressive and multi-scan paths; accepting them expands format support beyond that build. Grayscale replication and stricter malformed-input rejection remain separate qualifications.

JPEG encoding implements SaveJPG's configured sequential Huffman 4:2:0 path, with standard tables and no smoothing, restart markers or optimized coding. AA&N arithmetic uses the verified binary32 profile; historical x87 evaluation remains unverified. The diagnostic interface accepts top-down RGBA and grows its output. Screenshot commands now pass bottom-up pixels and the actual fixed-size hunk output buffer; overflow rejects instead of writing outside that allocation.
